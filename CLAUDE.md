# kogut

A maintenance agent for the AKogut portfolio repositories, built on Claude Code. It runs locally and on demand as the `/kogut` skill. There is no server. The only thing on a schedule is the daily digest, which is read-only on GitHub and runs without the model. On GitHub it acts as its own GitHub App, `kogut-agent[bot]`, so the history keeps the agent's work apart from the owner's.

Mandate: keep the watched repositories up to date and green (Dependabot PRs, CI health, repository hygiene). kogut does not build features.

kogut runs on the owner's Claude subscription, through whatever account Claude Code is logged in with. Nothing in it may require an API key: no Agent SDK, no `ANTHROPIC_API_KEY`, no cloud runner. Every step that uses the model stays inside a local Claude Code session.

## Layout

- `.claude/skills/kogut/SKILL.md`: the procedure `/kogut` follows, covering the parts that need judgement.
- `scripts/`: the deterministic half, meaning collection, policy and every action. `signals.jq` holds the rules that need no judgement, and `issues.jq` decides what happens to each kogut issue.
- `kogut.config.json`: watched repositories, their local clones, the policy numbers and the App's id.
- `.claude/settings.json`: what the agent may run without asking, and what it may never run.
- `.env`: one Discord webhook per repository (see `.env.example`). It is gitignored and the model may not read it; only `scripts/notify.sh` does.
- `~/.config/kogut/kogut-agent.private-key.pem`: the App's private key, outside the repository. The model may not read it; only `kogut_app_token` in `scripts/lib.sh` does. `scripts/app.sh` registers the App and checks its installation.
- `.kogut/`: run state, gitignored. `state.json` is the last snapshot, `outbox/` holds reports and issue diagnoses waiting to be sent, `sent/` holds the reports already posted and the text of opened fix PRs, `fixes/` holds the worktrees of fixes in progress, `digest/` is the daily digest's own outbox, and `digest.log` is what its scheduled runs print.
- `tests/`: policy tests for `signals.jq` against `tests/fixtures/state.json`, with the clock pinned by `KOGUT_NOW`.
- `.githooks/pre-commit` and `.gitleaks.toml`: secret scanning. The custom rule catches Discord webhook URLs.
- `.github/`: CI (lint, policy tests, secret scan), Dependabot for actions, templates and the social preview with its HTML source.

## Rules for changing kogut

- Policy lives in code, not in the prompt. A rule that code can check (author, checks, age) belongs in `signals.jq` or in the script that acts on it, so a persuasive PR body cannot talk the model past it.
- Every action goes through a script under `scripts/`. The raw commands (`gh pr merge`, `gh pr create`, `git push`) are `ask` rules in `.claude/settings.json`, never `allow`. An action that needs the owner's approval is an `ask` rule, not a sentence in the prompt.
- A script that writes on GitHub uses the App's installation token from `kogut_app_token`, never the owner's `gh` login. Assign it to a variable and check that it is not empty before use: an empty `GH_TOKEN` makes `gh` fall back to the owner. The one exception is `scripts/dependabot-command.sh`: Dependabot takes commands only from users with push access and refuses the App, so it posts under the owner's login, after checking that `gh` is logged in as the owner, and all it can post is the command itself.
- Scripts accept repository names only from `kogut.config.json` (`kogut_require_repo` in `scripts/lib.sh`).
- Scripts are bash, `gh` and `jq`, and must work with macOS bash 3.2. Run `shellcheck scripts/*.sh tests/*.sh` after changing them.
- A rule changed or added in `signals.jq` or `issues.jq` gets a check in `tests/run.sh`. Run `./tests/run.sh`.
- `main` takes pull requests only (ruleset `main`: squash, linear history, required checks `Lint`, `Policy tests` and `Secret scan`). All seven portfolio repositories use the same ruleset, and the repository admin can bypass it on pull requests only. `gh pr merge` is an `ask` rule here, so the owner approves every merge, and it never carries `--admin`. Commits are authored by the owner, with no co-author trailer.
- kogut reads with the owner's `gh` login, which carries the admin bypass, and writes as the App, which is on no bypass list, with that one exception. `scripts/merge-dependabot.sh` never passes `--admin` and refuses to merge unless the gate in `signals.jq` says the PR is ready; keep it that way. `gh pr merge` with `--admin` is denied in `.claude/settings.json`.
- Fix PRs are opened by `kogut-agent[bot]` through `scripts/open-fix-pr.sh`, and the owner merges them on GitHub; kogut never merges its own fixes. What kogut writes in the watched repositories is signed as kogut and does not mention the tooling behind it.
- This repository is public. Nothing personal or secret goes into it: webhooks stay in `.env`, and run output stays in `.kogut/`.
- Everything is in English: reports, Discord posts, code, docs and commits.

## Roadmap

1. Done: `/kogut analyze`, a read-only report in the terminal.
2. Done: Discord. `/kogut` posts each repository's report to its own channel.
3. Done: Phase 0. Required checks, auto-merge, Dependabot config and alerts in every repository.
4. Done: merging Dependabot PRs through `scripts/merge-dependabot.sh`, with the owner's approval for each merge. One call can name several PRs of one repository, which the owner approves together by number (agreed on 2026-11-03); each is still judged on its own, and a major is a call of its own.
5. Done: fixes in a worktree (`/kogut fix`), opened by `kogut-agent[bot]` after the owner approves, and merged by the owner.
6. Done: issues as kogut's memory. `scripts/issues.sh` keeps one issue per finding (keys from `signals.jq`, policy in `issues.jq`) and closes it once the finding is gone.
7. Done: follow-up. `kogut_prs[]` in `signals.jq` says what each of kogut's PRs needs, and only the owner's reviews count. `scripts/update-fix-pr.sh` pushes a follow-up commit (fast-forward only, up to `policy.followup_limit`) or answers with a comment.
8. Done: tasks. Issues the owner labels `kogut-task` become PRs (`open-fix-pr.sh --task`) or answers (`task-reply.sh`). Only the owner's label counts, as `tasks[]` in `signals.jq` decides and `kogut_task_check` verifies on GitHub. kogut takes on its own alerts issue (while a package is uncovered by Dependabot) and its issues for majors without a label; the owner agreed to that on 2026-10-30 and still approves and merges every PR. The scope is maintenance plus migrations, never features (decided by the owner on 2026-10-30).
9. Done: lockfile fixes. `scripts/fix-lockfile.sh` runs npm (`install --package-lock-only`) or pnpm (`install --lockfile-only`, at the `packageManager` version) in a fix worktree, with scripts and pnpmfile hooks off, and refuses when the fix touches `.npmrc` or a pnpmfile. The owner approved lockfile-only installs on 2026-10-30. `pnpm update` is not used: it installs `node_modules` even with `--lockfile-only`.
10. Done: security fixes skip the cooldown. `fixes[]` in `signals.jq` lists the alerts a Dependabot PR fixes (an update leaves the vulnerable range, in the alert's directory), and a fix for an alert at `policy.cooldown_skip_severity` (high) or worse is not held by the cooldown. Every other blocker still applies.
11. Done: commands to Dependabot. `command` on each Dependabot PR in `signals.jq` names `rebase` (behind, in conflict for a day, or red on an older base) or `recreate` (Dependabot says someone else edited it), from Dependabot's and the owner's comments after the head commit only. `scripts/dependabot-command.sh` posts it under the owner's login, once per head commit, with the owner's approval. It cannot go out as the App, because Dependabot answers "Sorry, only users with push access can use that command" (owner agreed on 2026-11-03).
12. Done: progress. `/kogut progress` runs `scripts/progress.sh` (two GitHub searches plus each repository's comments and alerts, read-only) and `scripts/progress.jq`, which does every count and renders the report. The model adds links, never figures.
13. Done: workflow runs. `action` on each red or disabled workflow in `signals.jq` names `rerun` (failed on the current head, not retried, under 3 failures in a row), `dispatch` (last run on an older commit or too old to retry, and the workflow has `workflow_dispatch`; once per head) or `enable` (disabled for inactivity). `scripts/run-workflow.sh` acts as `kogut-agent[bot]` with a token narrowed to `actions: write`, with the owner's approval. The App needs the `actions: write` permission, which the owner grants in its settings. With `--pr <n>` the script runs a workflow on the branch of Dependabot's or kogut's PR, for a check the PR does not get, up to `policy.pr_run_limit` times per head. Such a run has the repository's secrets, so a Dependabot PR must be past its cooldown (`in_cooldown` in `signals.jq`), and a PR that changes `.github/workflows/` needs `--workflows`.
14. Done: daily digest. `scripts/digest.sh` posts each repository's state to its channel: `collect.sh` reads with the owner's login, `digest.jq` renders with no judgement, and `notify.sh` delivers. No model, no App token and no write on GitHub, so it spends nothing from the subscription. `scripts/digest-schedule.sh` puts it on launchd at 09:00 local time. The owner reversed the earlier "no cron" decision for this on 2026-11-03; everything that acts stays in `/kogut`, behind approval.
15. Done: Node runtime watch. `collect.sh` records each repository's Node pin (`.nvmrc`, else `.node-version`) and `engines.node` from the default branch, and Node's release schedule once per run. `runtime` in `signals.jq` gives the pin's line, its phase, the Active LTS line and whether the pin is outside `engines`. A line past its end of life or a pin outside `engines` is the finding `runtime:node`; a line on maintenance is only mentioned. Without the schedule, or when a file could not be read, nothing is flagged and an open issue stays open. The fix goes through `/kogut fix`.
16. Done: dismissing alerts. `scripts/dismiss-alert.sh` dismisses every open alert of one package in one manifest as `kogut-agent[bot]`, with GitHub's reason and a comment on record, and `scripts/dismiss.jq` decides: a critical alert never, a high one only with `--severe`, and never a package an open Dependabot PR fixes in that directory. A sweep only proposes a dismissal; the script runs when the owner named the package and asked, and the owner approves the call. A dismissal can be reopened on GitHub. The App needs the `vulnerability_alerts: write` permission (Dependabot alerts), which the owner grants in its settings.
17. Done: pruning branches. `branches` in `signals.jq` calls a branch prunable only when its tip is exactly the head of a PR from this repository merged into the default branch, it is not the default branch or protected, and no open PR uses it as head or base; everything else is kept with its reason. `scripts/prune-branches.sh` deletes the branches named in the call, as `kogut-agent[bot]` with a token narrowed to `contents: write`, only when the owner asks and with the owner's approval of the list. `digest.jq` shows the count, which does not change a report's colour.
