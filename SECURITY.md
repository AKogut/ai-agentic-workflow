# Security policy

## Reporting a vulnerability

Please do not open a public issue. Report it privately through [GitHub's vulnerability reporting](https://github.com/AKogut/ai-agentic-workflow/security/advisories/new). I will acknowledge it within a few days.

Reports that matter most here are ways to make kogut act beyond its policy: prompt injection through PR bodies, release notes or CI logs that leads to a merge, a write or a leaked secret.

## How the project protects itself

| Risk | Control |
|---|---|
| Instructions hidden in Dependabot PR bodies, release notes or CI logs | Treated as data by the skill. The model may run only allow-listed, read-only commands. Merges, fix PRs, issue changes, pushes and repository edits are denied or require the owner's approval in [`.claude/settings.json`](.claude/settings.json). |
| The model talked past the merge policy | The policy is code ([`scripts/signals.jq`](scripts/signals.jq)), covered by [tests](tests/run.sh). The model can hold a PR back, but it cannot merge past a blocker. |
| Leaked Discord webhooks | URLs are kept only in a gitignored `.env`, which the model is denied from reading. [`notify.sh`](scripts/notify.sh) reads them, accepts only Discord webhook URLs and never prints them. |
| Mass pings through quoted text | Every Discord message is sent with mentions disabled. |
| Secrets committed by mistake | A [pre-commit hook](.githooks/pre-commit) and a CI job scan with gitleaks, including a rule for Discord webhooks. GitHub secret scanning and push protection are enabled. |
| A malicious package in a Dependabot update | Dependabot branches are never installed or run locally, only in GitHub's CI. A 3-day cooldown applies before an update counts as ready, so a hostile release has time to be caught and pulled. Only a PR that fixes a critical or high alert skips it (`cooldown_skip_severity`), because there the known vulnerability is the greater risk. [`signals.jq`](scripts/signals.jq) decides that from the alert's vulnerable range and directory and the versions in the part of the PR that Dependabot writes itself, never from quoted release notes, and the owner still approves the merge. |
| Package code running during a lockfile fix | [`fix-lockfile.sh`](scripts/fix-lockfile.sh) runs npm or pnpm in lockfile-only mode with `--ignore-scripts` and, for pnpm, `--ignore-pnpmfile`, in an environment without GitHub tokens. It refuses when the fix touches `.npmrc` or a pnpmfile, and it deletes any `node_modules` that appear and fails. Only registry metadata is read, and pnpm must be the version the repository pins. `pnpm update` is never used, because it installs packages even with `--lockfile-only`. |
| Unreviewed changes to `main` | A ruleset allows changes only through pull requests that pass the required checks: squash merges, linear history, no force pushes, no deletion. Only the owner can override a red check, and only on a pull request. |
| kogut merging past a red check | kogut writes on GitHub as its own GitHub App, `kogut-agent`, which is on no ruleset's bypass list, so the owner's override is not available to it. [`merge-dependabot.sh`](scripts/merge-dependabot.sh) and [`open-fix-pr.sh`](scripts/open-fix-pr.sh) refuse to run without the App's token rather than fall back to the owner's login. The merge script never passes `--admin` and merges only what the gate in `signals.jq` calls ready. Raw `gh pr merge` needs the owner's approval on every run, and with `--admin` it is denied. |
| A leaked App private key | The key lives in `~/.config/kogut/` (directory mode 700, file mode 600), outside the repository, and the model is denied from reading it. Only [`lib.sh`](scripts/lib.sh) opens it, to ask GitHub for an installation token or whether the App is installed on a repository. Each token it mints covers one repository and expires after an hour. The App can write code, PRs, issues and workflow files, and run workflows, in the watched repositories, and nothing else. A leaked key is revoked in the App's settings. |
| kogut flooding or closing issues on a hostile prompt | [`issues.sh`](scripts/issues.sh) opens issues only for findings that `signals.jq` produces, and opens one for a major only when the model writes a diagnosis. It changes or closes only open issues that the App itself filed with the `kogut` label, and it closes one only when the finding is gone from a fresh collection, never on the model's say-so. The policy is in [`issues.jq`](scripts/issues.jq) and is tested. Diagnoses are scanned with gitleaks, and the owner approves each run. |
| kogut spamming Dependabot, or a comment steering it | [`dependabot-command.sh`](scripts/dependabot-command.sh) posts only `@dependabot rebase` or `@dependabot recreate`, and only when [`signals.jq`](scripts/signals.jq), on a fresh collection, names that command for the PR. It asks at most once per head commit. Only comments from Dependabot and from the owner count, so a stranger cannot fake Dependabot's answer or a request. The owner approves each call. This is the one write kogut makes under the owner's login, because Dependabot refuses commands from the App: the script checks that `gh` is logged in as the owner, and the comment can only be the command. |
| kogut running workflows on a hostile prompt | [`run-workflow.sh`](scripts/run-workflow.sh) can retry the failed jobs of a default-branch run, start a workflow on the default branch, or turn back on a workflow GitHub disabled for inactivity, and only when [`signals.jq`](scripts/signals.jq), on a fresh collection, names that action. A run is retried at most once, and not after 3 failures in a row. A workflow is started at most once per head commit and never with inputs. The token for this carries `actions: write` and nothing else. A workflow the owner disabled stays disabled. The owner approves each call, and raw `gh run rerun`, `gh workflow run` and `gh workflow enable` need approval too. |
| A hostile release reaching the repository's secrets through a run on a PR's branch | `run-workflow.sh --pr` runs a workflow on the branch of a Dependabot or kogut PR only. Unlike Dependabot's own runs, such a run has the repository's secrets, so a Dependabot PR must be past its cooldown, the same wait that guards a merge. A PR that changes `.github/workflows/` needs `--workflows`, which the owner sees in the prompt. A workflow runs at most `policy.pr_run_limit` times per head, not while one is going and not after one passed. A kogut PR has no cooldown, so its fresh lockfile rests on the owner's approval of the call. |
| kogut dismissing an alert to make a report look clean | A sweep only proposes a dismissal: [`dismiss-alert.sh`](scripts/dismiss-alert.sh) runs when the owner named the package and asked, and the owner approves the call. On a fresh collection, [`dismiss.jq`](scripts/dismiss.jq) refuses a critical alert always, a high alert without `--severe`, and a package that an open Dependabot PR fixes in that directory. It takes one of GitHub's reasons and a comment of at most 280 characters, scanned with gitleaks before anything is sent, so the record of why stays on the alert. The token carries `vulnerability_alerts: write` and nothing else. A dismissal can be reopened on the alert's page on GitHub. |
| A scheduled job acting without the owner | One launchd job, [`daily.sh`](scripts/daily.sh), runs outside a session, without the model, under the owner's login session. [`digest.sh`](scripts/digest.sh) only reads GitHub and posts to Discord; PRs show as numbers without their titles, so no text from anyone else reaches a channel. [`auto-merge.sh`](scripts/auto-merge.sh) does write: as `kogut-agent[bot]`, it merges what `auto_merge` in [`signals.jq`](scripts/signals.jq) calls eligible, and nothing a model or a PR body said can change that. Eligible means ready by the gate, a patch, a direct dev dependency by both the title and Dependabot's own commit metadata, read from a front matter that must stand alone at the end of the message so quoted text cannot count, a head commit only Dependabot wrote, at least `cooldown_days` old even when it fixes a high alert, and a default branch that is not red, at most `limit_per_repo` per repository per day. Whatever cannot be read keeps a PR out, each merge is pinned to the commit judged, and every outcome is recorded and shown in the digest. **What the owner gives up:** review of this tier. A hostile or broken patch to a dev dependency that outlasts the cooldown and passes CI lands on the default branch with nobody having looked, and from there CI runs it with the repository's secrets. The owner accepted that on 2026-11-03. `enabled: false` in `policy.auto_merge`, [`hold.sh`](scripts/hold.sh) or `digest-schedule.sh uninstall` stops it. |
| kogut writing in a repository the owner is working in | [`hold.sh`](scripts/hold.sh) keeps its state outside the repository, so a run from any worktree sees it. While a repository is on hold, every script that writes on GitHub refuses it, dry runs included, and `issues.sh` and `auto-merge.sh` skip it. A hold file that cannot be read, is empty or has the wrong shape holds every repository, and `hold.sh` will not overwrite it. The model never lifts a hold unless the owner asks. |
| kogut deleting someone's work | [`prune-branches.sh`](scripts/prune-branches.sh) deletes only branches named in the call, so the owner reads the list in the prompt, and it runs only when the owner asks. [`signals.jq`](scripts/signals.jq), on a fresh collection, must call each one prunable: its tip is exactly the head of a PR from this repository merged into the default branch, it is not the default branch or protected, and no open PR uses it as head or base. A branch with no PR, an unmerged one or one with later commits is never prunable, and if the branches or the open PRs cannot all be read, nothing is. The tip is read again just before each delete, names are validated before they reach a URL, and the token carries `contents: write` and nothing else. Each deleted branch is printed with its tip and PR, whose "Restore branch" button brings it back. |
| kogut reading a secret | [`collect.sh`](scripts/collect.sh) lists each repository's Actions secrets with the owner's login, and keeps each one's name and date. That endpoint returns no value, and kogut has no way to read or set one, so only the owner can rotate a secret. A secret old enough that it may have expired is named in the repository's report, digest and issue. A name is not a value, but in a public repository that issue is public, so a name that must stay private goes in `policy.secret_ignore`. |
| A log steering kogut's retries, or reaching a report | [`run-cause.sh`](scripts/run-cause.sh) reads the failure text of a red workflow's latest failed run, and [`causes.jq`](scripts/causes.jq) reduces it to `{kind, signature}`, a name from a fixed table. That is all it prints, so log text never reaches the snapshot, a report, the digest or an issue. Anyone who can change a job can print a signature. A forged `infra` signature can cost at most one retry of that run, and only below `policy.infra_retry_limit` failures in a row, and every failed job must carry one, so one unexplained job leaves the run `unknown`. A forged `credentials` signature can only stop a retry, and that one matches whole annotations and `##[error]` lines alone, because a test suite can log the same words. No signature is taken as proof of a fix. |
| kogut writing a feature nobody approved | A feature starts from the owner's label `kogut-feature`. kogut answers with a plan, and writes code only after the owner's label `kogut-plan-approved`, newer than the latest plan and still on the issue, which [`feature.jq`](scripts/feature.jq) decides and `open-fix-pr.sh --feature` asks on GitHub right before opening. Only the App can post a plan, and a stranger's label counts for nothing. Only this path allows a `feat` title. The PR is a draft within `policy.feature`'s size limits, cannot change `.github/workflows/`, and is merged by the owner. Only repositories in `policy.feature.repos` take features. |
| Hostile code running on the owner's machine | kogut does not install dependencies or run a repository's code, for features as for fixes, so CI is the only runner and install scripts never run here. |
| A stranger handing kogut work | A task is an issue labelled `kogut-task`, and only the owner's label counts: the latest such label must come from the owner. [`signals.jq`](scripts/signals.jq) decides that and tests cover it, and `open-fix-pr.sh --task` and `task-reply.sh` check it again on GitHub before they act. kogut also takes on two kinds of its own issues without a label: alerts that no Dependabot PR covers, and majors. They count only when the App itself filed the issue, so copying kogut's marker into another issue does nothing. The task's text is input, not instructions. Titles stay limited to maintenance types, the owner approves the PR, and the owner merges it. |
| A stranger's review or comment steering kogut | On kogut's own PRs only the owner's reviews and comments count as feedback. That is decided in [`signals.jq`](scripts/signals.jq) and tested, and [`pr-feedback.sh`](scripts/pr-feedback.sh) counts anyone else's words but never quotes them. A follow-up pushes only as a fast-forward from the head it started from, at most `followup_limit` (3) times per PR, and the owner approves each push. |
| A fix PR that leaks a secret or plants a hostile workflow | Nothing leaves the machine before [`open-fix-pr.sh`](scripts/open-fix-pr.sh) scans the changed lines and the PR text with gitleaks. A change under `.github/workflows/` needs `--workflows`, which the owner sees in the approval prompt, because a workflow on the PR branch runs with the repository's secrets before review. The owner sees the diff (`--dry-run`) before approving, and only the owner merges a fix. Titles are limited to maintenance types (`fix`, `ci`, `build`, `chore`, `docs`, `test`). |
| kogut rewriting its own rules | kogut watches this repository too, so a fix PR here can change its scripts and its skill. The owner reviews and merges it like any fix, and kogut never merges its own. No kogut PR can change a `.claude/settings.json`, here or in any repository: `kogut_stage` in [`lib.sh`](scripts/lib.sh) refuses it before anything leaves the machine, for new PRs and follow-ups alike, so kogut cannot propose what it may run without asking. The owner edits that file by hand. Its Dependabot updates only GitHub Actions, which never qualify for unattended merges. |

## Supported versions

Only `main` is maintained.
